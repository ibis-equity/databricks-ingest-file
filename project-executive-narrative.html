Executive Overview

Databricks Ingest File

A practical data ingestion solution that takes raw files from operational sources, loads them into Databricks, and creates a reliable path from file-based input to analytics-ready data. It reduces manual effort, supports automated intake, and creates the foundation for a bronze-layer lakehouse architecture.

GitHub repository: https://github.com/ibis-equity/databricks-ingest-file

DLT pipeline documentation: notebooks/dlt_customer_pipeline.html

Why this project matters

Most businesses still receive data in files: CSV exports, JSON payloads, flat files, and tabular extracts delivered by applications, vendors, or internal processes. Those files are often not immediately useful for analytics because they require validation, normalization, and loading into a governed platform.

This project addresses that challenge. It monitors a source directory, discovers new files, validates them, loads them into Databricks, and tracks what has already been processed so the same file is not ingested again. In a business sense, it reduces manual effort, shortens the time from raw file to usable data, and creates a more reliable operational data foundation.

What happens when files are dropped

When one or more files are dropped into the destination folder, the ingestion utility immediately begins its routine. It scans or listens for the new file, checks the file is valid and not still being written, and confirms it is not already in the processing ledger. Then it reads the file from CSV, JSON, or Parquet format, normalizes the schema, and uploads it into Databricks as a data table.

Once the load succeeds, the project moves the file into the processed directory so it is retained for traceability but not re-processed on the next cycle.

How this connects to the DLT customer pipeline

This ingestion utility is the front door for raw files. After the file is landed and loaded, the downstream dlt_customer_pipeline can process the resulting datasets through Bronze, Silver, and Gold layers.

In that model, the raw data from ingested files becomes bronze-layer source data. The DLT pipeline then discovers tables, standardizes records, repairs missing values, enriches them with reference data, deduplicates records, and produces executive analytics such as customer lifetime value, geographic revenue summaries, email analysis, and duplicate detection.
